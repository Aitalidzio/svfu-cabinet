# Чек-лист требований конкурса

Пересказ положения номинации «Вайб-кодинг» (задача «Цифровой деканат будущего»), разбитый на проверяемые пункты.
Отмечаем `[x]`, когда пункт сделан **и проверен руками**.

Сроки: работы принимают с 08.11.2026 19:00 до **22.11.2026 23:59 МСК**. Сайт должен работать до **28.11.2026** (день объявления итогов).
Отправленную работу можно заменить до дедлайна — оценивается последняя версия.

## 1. Обязательное ядро кабинета

- [x] **Вход и профиль.** Вход по логину и паролю. В профиле: ФИО, факультет (институт), направление, курс, группа.
- [x] **Расписание.** Занятия на сегодня и на неделю, аудитория, преподаватель. Переносы и изменения хорошо заметны.
- [x] **Успеваемость.** Оценки и зачёты по дисциплинам, сессия, понятный ответ на вопрос «как у меня дела с учёбой».
- [ ] **Заявки и справки.** Онлайн-заказ справки или подача заявления, у заявки виден статус.
- [ ] **Уведомления.** Новости и объявления деканата, напоминания о дедлайнах и изменениях.

Сценарий, который жюри почти наверняка пройдёт: **войти → расписание → оценки → подать заявку → увидеть её статус.**

## 2. Требования к прототипу

- [ ] Это работающий сайт по ссылке в браузере, а не макет (Figma и картинки не считаются).
- [ ] Стек подходит под задачу и масштабируется под разное число пользователей.
- [ ] Код написан ИИ-ассистентами, а процесс задокументирован.
- [ ] Все основные сценарии работают на телефоне шириной от **360 px**.
- [ ] Все данные вымышленные. Нет реальных ФИО, оценок, номеров зачёток, логинов и паролей. Прототип не подключён к настоящим системам вуза.
- [ ] Видно, что это **концепт для конкурса**, а не официальный сервис СВФУ.
- [ ] Официальный логотип вуза не используется. Свой логотип может перекликаться с ним по идее, но не копирует его.
- [ ] Сторонние библиотеки, шрифты, иконки и картинки используются только по разрешающей лицензии (список в [licenses.md](licenses.md)).
- [ ] Сайт открывается из России **без VPN** и работает до 28.11.2026.
- [ ] Для жюри есть минимум **два тестовых студента** с разными данными и аккаунт сотрудника.

## 3. Безопасность

- [ ] Студент видит только свои данные. Чужой профиль или чужую заявку нельзя открыть, даже если подставить другой id в адрес.
- [x] Пароли не хранятся в открытом виде.
- [ ] Ключи и пароли от сервисов (включая ИИ) не лежат ни в коде, ни в браузере пользователя.

## 4. Что отправить

- [ ] Ссылку на прототип и тестовые аккаунты (логины и пароли) — в комментарии к работе.
- [ ] Ссылку на репозиторий с доступом для жюри.
- [ ] Описание процесса создания в PDF или по ссылке, со скриншотами:
  - [ ] какую проблему студентов решает кабинет, почему выбраны эти разделы, что сказали однокурсники;
  - [ ] полный перечень ИИ-инструментов, IDE и сервисов и для чего использовался каждый ([ai-process/tools.md](ai-process/tools.md));
  - [ ] ключевые промпты и диалоги с ИИ с привязкой к этапам ([ai-process/journal.md](ai-process/journal.md));
  - [ ] скриншоты ключевых шагов, от идеи до готового кабинета, включая удачные и неудачные варианты;
  - [ ] как устроены вход, хранение данных и защита — простыми словами;
  - [ ] что делали вручную.
- [ ] Видео до 5 минут (по желанию, но приветствуется), включая работу с телефона.

## 5. Критерии оценки (по 10 баллов, итог — среднее)

1. **Проработанность идеи.** Понятна проблема, сценарии построены вокруг реальных задач, ядро сделано полностью. Смелые идеи повышают оценку.
2. **Масштаб использования ИИ.** Продуманный процесс, качественные промпты, файлы для ИИ-агентов, работа с ошибками ИИ, ИИ для дизайна и контента, наглядное описание.
3. **Имплементация.** Всё работает без ошибок, данные сохраняются, есть мобильная версия, безопасность, работающие тестовые аккаунты.
4. **Качество.** Цельный современный дизайн, понятная навигация, продуманные пустые состояния, ошибки и загрузка, скорость и доступность.
